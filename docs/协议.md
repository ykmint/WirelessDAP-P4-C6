# WirelessDAP v1

小端帧头 `<2sBBIH`，10 字节：`WD`、版本 1、操作码、32 位序号、16 位负载长度。负载最多 256 字节。响应操作码=请求|0x80，序号相同；响应负载第一个字节是状态，0 成功、1 未鉴权、2 设备忙、3 参数/序号错误、4 电源/电压异常。

操作 1：32 字符 ASCII 访问令牌。操作 2：64-byte CMSIS-DAP 数据包，末尾补零。操作 3：读取 JSON 电压/故障状态。操作 4：单字节目标供电控制，0 关、1 开。鉴权后请求序号严格递增，失败不会自动重试。一次仅有一包 CMSIS-DAP 在途。

TCP：端口 6123，帧头后按长度读取完整负载；EOF 或超时终止会话。

BLE：服务 `965a0001-0d7e-4e4d-9a5e-f742e87dc610`。RX 的编号为 0002，Write with response，将整个帧分成最多 20 字节的有序片段。TX 为 0003，Read，返回最近完成响应；电脑轮询直到序号匹配。单次只允许一个完整请求在途，分片超时 5 秒。以 Read 而不是 notification 返回响应，避免通知丢失/流控差异；这不是追求吞吐的实现。

BLE 与 TCP 执行共用互斥锁，全部 DAP 操作由 ARM 参考实现处理，禁用 JTAG/SWO/UART/Atomic 批命令。板上没有 NRST，电脑端禁止硬件复位。电源异常会关闭目标输出并将 SWD 引脚置为输入；错误会话需要重新连接。
